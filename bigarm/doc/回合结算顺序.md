# 单回合结算顺序

本文记录**当前代码实际执行的一整个回合**，作为以后加入新机制时讨论和修改时序的基线。阶段编号沿用[游戏规则与判定](游戏规则与判定-1.md)中的 R0～R8；以后可以调整阶段及内部顺序，调整时同步更新本文、实现和对应判例。

- 整理日期：2026-11-24。
- 当前规则版本：`2026-11-25`，已纳入 V2 新招式与本轮确认；基础实现沿用提交 `0fbb24f`。完整清单见 [招式清单.yaml](招式清单.yaml)，变更说明见 [v2-实现说明](v2-实现说明.md)。
- 主要依据：[判定引擎](../rules/engine.js)中的 `beginRound`、`advance`、`makeHits`、`resolveHit`、`resumeRound`，以及[招式目录](../rules/catalog.js)。
- 本文重点是游戏判定。网页的搜索、按钮、动画和倒计时不决定判定次序；房间服务在引擎前后的处理单独列在文末。

## 一、总顺序

**选招完成 → R0 校验 → R1a 体力流失 → R1b 激活 → R1c 优先禁法 → R1d 招式库存 → R2 独立法术 → R3 攻击准备、排序和互攻标记 → R4 逐份投递 → R5 祝福分配 → R6 扣血、判死 → R7 超限弃置 → R8 胜负与回合维护。**

| 阶段 | 做什么 | 什么时候才能进入下一阶段 |
| --- | --- | --- |
| R0 快照与校验 | 根据回合开始状态验证所有存活者的行动。 | 所有行动均合法。 |
| R1a 开局体力流失 | 按已选行动和已有钻心咒直接减生命，不视为伤害。 | 所有开局体力流失完成，不提前移除本回合行动者。 |
| R1b 激活 | 按座位支付成本，获得基础收益、造盾、登记固有防护及新持续/延迟攻击。 | 所有行动均激活完成。 |
| R1c 优先禁法 | 统一处理锤锤锤的 2 级禁法，固有免控已经可用。 | 所有优先禁法标记确定。 |
| R1d 招式库存 | 非基础行动各得 1 个同名库存；新普通独立法术被禁法取消的行动不获得。 | 所有本次库存收益确定。 |
| R2 独立法术 | 按座位处理小电、凤鸣祝福、治疗、持续闪避等攻击前效果。 | 所有法术完成，所需的小电移盾选择完成。 |
| R3 攻击准备 | 生成本回合所有攻击，固定目标、点数、批次顺序和互攻压制结果。 | 攻击队列完整建立。 |
| R4 攻击投递 | 按队列检查压制、对空、免疫、防法，处理命中、持有盾、伤害记录和命中回调。 | 所有攻击及其中途选盾完成。 |
| R5 祝福分配 | 按座位对每次可减伤的生命伤害分配祝福值。 | 所有相关玩家均完成分配。 |
| R6 扣血与判死 | 扣除最终生命伤害，统一判死，移除指向死亡目标的持续攻击。 | 最终存活集合确定。 |
| R7 持有量整理 | 存活者依次作必要弃置，恢复所有盾位及数量限制。 | 所有存活者的装备合法。 |
| R8 结束与维护 | 确定胜负，记录完成的回合，推进回合编号并清理到期效果。 | 输出本回合最终结果。 |

R0～R8 是规则层的阶段编号，不与代码里的 `job.phase` 一一对应：R0、R1a、R1b 在 `beginRound` 中；R1c、R1d 对应 `priority` 分支；R2 对应 `spells`；R3 在该分支结束时调用 `makeHits`；R4 对应 `hits`；R5 和 R6 位于 `blessing` 分支；R7 和 R8 位于 `discard` 分支，完成后才标记 `done`。以后拆分或新增阶段时，应同时检查这些入口和续结位置。

以下三条贯穿整个流程：

1. **同时选招不等于所有效果同时改状态。** 选招依据同一回合开始状态；执行过程采用下述确定顺序。
2. **伤害不会使后续攻击提前取消。** 本回合攻击都处理完、祝福分配完后才扣除伤害并判死。体力流失虽提前直接减生命，也不提前取消已选行动。
3. **玩家的中途选择会暂停整个结算。** 选盾期间不会让下一份攻击先行处理。

## 二、R0：固定回合开始状态并校验

以传入的对局状态为准，取生命大于 0 且未标记离场的玩家，按座位升序确定本回合行动者。

逐人检查：

1. 是否提交当前启用目录中的一个行动。
2. 回合开始时的基础资源、祝福及招式库存是否足够支付各自成本。比如两幽灵闪资源不能用基础 BFYC 临时替代。
3. 合成幽灵盾时，是否已经持有两面真实泡沫盾。
4. 单体、地震、溅射目标是否为其他存活者；地震是否为一至两个不同目标。
5. 回旋镖方向是否为顺时针或逆时针。
6. 实际基础动作的连续限制：超闪不能连续两回合使用，闪和超闪合计不能连续三回合使用。

所有校验都读取**回合开始状态**，不能先让某人的动作产生资源，再拿这份资源使另一个本来非法的行动通过校验。

全部合法后，复制状态开始结算；不修改调用者传入的状态。任一行动非法时，不返回一个已经部分支付或部分生效的新对局状态。

同一玩家仍只有一个新行动；已有持续攻击无需另占本回合行动。

## 三、R1：开局体力流失、激活、优先禁法和库存

### 3.1 R1a：不可免疫的体力流失

先固定 R0 的行动者，再按座位检查其已选行动及已有有效状态：

1. 幽灵毁灭之剑、阿西吧各让使用者流失 1 体力。
2. 已有钻心咒状态下实际选择基础 S/C，流失 2 体力；使用成本含 S/C 的招式或仅拥有等效防法不触发。
3. 直接减少生命，单独记入 `lifeLoss`，不进入伤害账本，不经过免伤、免控、盾和祝福。

此时生命可以非正，但 R0 已固定的行动者和目标集合不变。即使自己的体力代价令生命变成 0，本回合已选攻击、收益和法术仍继续，R6 才统一判死。新钻心咒从下一回合开始，因此施放当回合不触发这项流失。

### 3.2 R1b：以行动为单位支付和激活

按座位升序完整激活每名玩家的行动：

1. 支付本次基础资源、祝福或招式库存成本；后续被取消、压制、防住都不退费。
2. 登记固有免伤、免控等级，包括六拳合一、小电、凤之守护、雷闪和阿西吧。阿西吧的优先无敌为 2 级免伤加 2 级免控。
3. 基础动作立即获得资源：通常 1，持有相应生产器时总共 3；不另发重复的 basicB 等库存。
4. 更新最近两次实际基础动作历史，非基础行动记占位。
5. 制造真实装备；幽灵盾消耗两面真实泡沫盾。招式库存中的泡沫盾不作为材料。
6. 登记持续/延迟攻击。普通持续攻击区间为 `[t,t+N-1]`；飞刀为 `[t+1,t+1]`。这里只登记，R3 才生成有效攻击。

所有玩家完成此步后才开始优先控制。因此座位靠后的固有免控也已经可用。新盾能在本回合挡攻击，也可能在 R2 被小电移除。容量可暂时超限，到 R7 再整理；后来移除生产器不追回已发放基础收益。

### 3.3 R1c：锤锤锤的优先禁法

按座位处理全部锤锤锤。对其指定目标检查 2 级免控：足够则免疫，不够则标记取消该目标本回合的新普通独立法术。

- 六拳合一的 1 级免控不够；凤之守护、雷闪和阿西吧的 2 级免控足够。
- 小电只有 2 级免伤，不能凭此抵挡控制。
- 不要求锤锤锤的物理攻击命中，点数压制、防法或普通盾承伤不阻止这项优先法术。
- 锤锤锤的优先法术不被其他锤锤锤取消。互相指定时各自生效，不产生取消循环。
- 固有防护、旧状态、攻击伤害、命中回调不取消。比如凤鸣祝福可取消，但凤鸣的法术攻击保留。

### 3.4 R1d：取得招式库存

非基础行动各增加 1 个同名库存，但其本回合新普通独立法术被禁法取消时不增加；旧库存不受影响。锤锤锤的法术例外保留，因此仍取得同名库存。

普通互攻压制、免疫、防住或命中盾不取消库存收益。库存独立于实际盾和持续状态：盾被打掉不扣库存，消费幽灵闪库存不删除其防法。持续攻击以后自动产生的投递不算又出一次新招，不重复发库存。

## 四、R2：攻击前的独立法术

优先禁法和库存收益完成后，按行动者座位升序处理未被取消的普通独立法术。每名玩家只有一个新行动；当前每个行动至多命中下表的一种独立法术分支。

| 效果 | 当前处理 |
| --- | --- |
| 小电 | 先检查目标免控。未被免控阻止时，从目标当前可被小电移除的装备中选一件，立即移除。无候选时无装备被移除；一件候选自动确定，多件候选由受术者选择。 |
| 凤鸣九天的祝福 | 使用者立即获得 3 祝福值，不依赖稍后攻击是否命中。所得祝福可在本回合 R5 使用。 |
| 回一滴血 | 使用者立即回复 1 生命，并按当前生命上限截顶。R6 不再补做一次治疗。 |
| 幽灵闪 | 登记当回合及下回合的超闪防法，共 2 回合。 |
| 连环闪 | 登记当回合及后两回合的闪防法，共 3 回合。 |
| 虚无闪 | 登记仅当回合的超闪防法，以及当回合及后两回合的单体、双目标、溅射免疫，共 3 回合。 |
| 钻心咒 | 检查指定对手的 1 级免控，未被阻止则登记下一回合起持续 15 回合的负面状态。 |
| 防六拳合一 | 登记本回合对应的专门防护，不获得基础资源。 |

凤之守护、雷闪等仅通过目录字段提供固有防护的行动，其防护已经在 R1 登记，无须在这里再登记一次。

小电移除的是**当前确实存在的一件装备**；多次小电依座位先后执行，后一个小电读取前一次移除后的列表。

持续状态以法术名和组件识别；同名同组件刷新为更晚的结束回合，不把旧状态的开始时间推后，不重复叠加钻心咒流失量。不同名状态并存，网页显示其法术名称。

只有全部 R2 完成后才生成攻击。禁法在 R1c 已完成，被取消的法术不会在此重新执行；当前没有旧锤、打断或递归反弹。太阳拳的 R2 控制目标改写和三连踹的 R3 攻击目标改写按本节末尾最新补充执行。

## 五、R3：一次性建立攻击队列

### 5.1 收集攻击来源

先收集本回合有效的持续/延迟攻击实例，再收集本回合新选的即时非持续攻击。目标集合使用 R0 固定的本回合参与者，不因 R1a 的体力流失而缩小。

- 持续实例满足 `start ≤ 当前回合 ≤ end`，并且其目标仍存活，才生成本回合攻击。
- 普通持续攻击包括 R1 刚建立的新实例，施放当回合会攻击；飞刀虽然已登记，但起始为下一回合，本回合不生成投递。
- 原使用者已经死亡，不取消其此前建立、目标仍活的持续攻击。
- 同一玩家的旧持续攻击与新行动可以一起存在；同种持续攻击重复施放是不同实例。

当前实现先按持续实例的起始回合、稳定实例编号整理旧实例，再生成攻击，以保证输入列表顺序不影响结果。

### 5.2 固定目标与事件参数

使用当前存活者的座位环，展开每个攻击的目标：

| 类型 | 展开方式 |
| --- | --- |
| 单体 | 指定的其他存活目标。 |
| 双目标 | 指定的一至两个不同目标；当前代码保留行动提交的目标数组顺序。 |
| 群体 | 其他全部存活者，按座位升序。普通群攻即使只剩一个目标，也保留群体标签。 |
| 溅射 | 主目标、其座位环两侧的存活邻居，去重并排除使用者；代码展开顺序为主目标、座位递增侧、座位递减侧。主目标使用单体标签，邻居使用溅射标签。 |
| 回旋镖 | 按所选方向从邻座起展开其他存活者，依次分配 3、4、5……点；对每个人都是一份单体攻击。 |

每份投递固定来源、目标、段号、点数、伤害基础值、范围标签、对空能力、真伤及穿透/无视类别。

地震选一个目标时为 15 点、1 伤害；选两个目标时为 7.5 点、各 1 伤害。回旋镖的点数在此按方向预分配，不在实际命中过程中递增。

### 5.3 建立批次并排序

普通攻击的所有目标、所有段构成一个连续批次。批次取得执行权后，内部按**先段号、再目标顺序**处理完，再轮到下一个批次。

- 火轮先第一段，再第二段。
- 万箭齐发先对所有目标处理第一轮，再对所有目标处理第二轮。
- 回旋镖例外地把每名目标的投递分别作为一个批次，所有批次从一开始就入队。

批次排序依次比较：

1. 攻击点数降序。
2. 使用者座位升序。
3. 生成次序升序。同一来源的旧持续实例按前述稳定次序生成，本回合非持续新攻击在其后生成。
4. 批次内部编号升序，作为最后的稳定排序键。

例如方向路径为甲→乙→丙→丁时，回旋镖给乙 3 点、丙 4 点、丁 5 点，实际执行顺序是丁→丙→乙。若有另一份 3.5 点攻击，则排序为 5→4→3.5→3。

### 5.4 对全部原始意图预先标记互攻

对每份“甲→乙”投递，查找全部“乙→甲”反向意图；存在一份能压制它的反向意图，就标记本投递被压制。

- 通常高点压制低点；双方任一为弧光时，仅数值高低关系反转为低点压制高点，等点仍抵消。攻击队列不重排；刀的保底、ber/刀点刀等特殊克制仍优先。
- 群攻只失去对该反向攻击者的投递，不因此失去对其他目标的投递。
- 多段和持续攻击也参与比较；每段使用其完整攻击点数。
- `ber` 克制刀；刀的普通低点、等点保底不能绕过这个克制。
- 刀点刀克制成本含大臂的其他攻击，被其余攻击克制；两把刀点刀互相抵消。
- 刀的保底使它不被普通点数比较压制，但仍须继续接受免疫、防法等检查。

互攻依据固定的原始意图，不随着实际命中结果删除或重算。反向攻击即使稍后被免疫、防住，或者其自身被另一份意图压制，也仍参加这次意图比较。特殊克制只改变压制关系，不改变该攻击的排序点数。

## 六、R4：按队列逐份处理攻击

每份投递依次经过下列检查；某一步结束该投递后，直接处理队列下一份。

### 6.1 压制与对空

1. **互攻标记**：已被压制或抵消则结束，不命中。
2. **对空**：当前目标在空中，而攻击不能对空，则结束，不命中。

对空读取目标此刻的状态。因此前一份攻击的打落成功后，后面的非对空攻击可以命中该目标。

### 6.2 免疫

依次检查：

1. 本回合固有免伤等级是否足以抵挡攻击等级；当前攻击默认 1 级。
2. 有效的范围免疫是否匹配。虚无闪不免疫普通群攻，但可匹配回旋镖的单体标签。
3. 当前持有的元素盾、雷达是否提供适用免疫。

虚无闪施放当回合另有超闪防法，仍可能在下一步防住适用的群攻；不能把“没有群体范围免疫”理解成“任何群攻都必定打中”。

对第三项，先按该攻击的穿透、无视类别排除不提供本次免疫的盾；其余盾任意一件满足免疫条件，就结束本次投递，所有盾均不消耗。

**此时检查的是全部适用盾的免疫，不是先让位置靠前的普通盾承伤。** 真伤仍接受这里的免疫检查。

### 6.3 基础防法及专门防护

未被免疫时，检查目标本回合基础动作所提供的防法，以及仍有效的持续防法。

- 基础方盾、圆盾等是当回合防法，与库存资源数量和持有盾不同。
- 同时拥有多种防法时，任意一种匹配即可；同一防法可以防住多份适用攻击，不因使用一次而消失。
- 火轮的闪防法只挡第一段；圆盾、超闪可防其适用的两段。
- 均衡之刃按行动身份判断：任意非基础行动可防住它。
- 六拳合一另检查“防六拳合一”的专门标记。
- 枪检查原行动身份：除实际基础 S/C 外其他行动均可防，不按库存或成本字母判断。
- 幽灵必杀检查任意非基础行动；基础六动作均不直接防。
- 幽灵毁灭之剑检查基础 Z 或原行动 `hasSpell` 分类；纯法术伤害不自动属于法术，分类清单见 YAML。被禁法不会抹去原行动身份。

防住后不算命中，也不消耗持有盾。流星锤在此触发特殊反噬：每名被基础/等效防法防住的目标，分别使来源受到一次 0.5 真伤；来源有足够固有免伤时不记录该反噬。反噬直接进入伤害账本，不重新生成一份反向攻击。

### 6.4 确认命中并确定条件伤害

通过前述检查后：

1. 火炬读取目标当回合基础动作；若是基础方盾，则将该次伤害改为 2。
2. 均衡之刃读取目标基础动作，确定其对应伤害。
3. 标记这一份投递已经开始命中处理，写入命中记录。

此后的持有盾抵挡仍属于命中。因此“命中”和“产生生命伤害”是两个不同结果。

### 6.5 持有盾路由或生命伤害

真伤跳过普通盾承伤，直接记录生命伤害。其他伤害按如下循环处理：

1. 从当前持有物中排除被本攻击无视的盾。无视不会消耗该盾。
2. 找出剩余候选中位置数最小的一组。当前普通盾通常为位置 3，生产器为位置 4。
3. 该组只有一件时自动使用；多件时，**由受伤者立即选择一件，然后继续本投递**。
4. 根据本攻击对所选盾的交互类型处理：

   | 交互 | 结果 |
   | --- | --- |
   | 普通单层盾抵挡 | 盾消失，本次伤害完全挡住，不溢出。 |
   | 幽灵盾普通抵挡 | 扣一层，本次伤害完全挡住；即使最后一层消失，也不溢出。 |
   | 穿透单层盾 | 盾消失，本次伤害继续寻找下一件可交互盾。 |
   | 通常穿泡级遇幽灵盾 | 最多扣两层；仍有层则挡住本次，层数耗尽则继续寻找下一件盾。 |
   | 穿云箭/拳打脚踢遇幽灵盾 | 整面消失；原为完整三层则挡住本次，原为残缺则继续寻找下一件盾。 |

5. 若需继续，重新读取持有物并回到第 1 步；若已无候选，则将全额伤害记入生命伤害账本。

穿透过程中不重做该投递已经通过的对空、免疫、防法检查。恢复选盾时也从这里继续，不重复记命中。

### 6.6 执行命中回调

持有盾挡住本次，或生命伤害已记录后，执行一次该投递的命中回调：

- 火轮：来源立即获得 1 圆盾；每段分别触发，生产器不放大这项收益。
- 天翻地覆：目标仍在空中且没有足够免控时，立即打落，供后续攻击读取。

一份投递穿过多面盾也只回调一次。被压制、对空失败、被免疫或被防住的投递不执行命中回调。

随后进入下一份投递，直到整个攻击队列完成。

**这里的“记录生命伤害”尚不直接减生命。R1a 体力流失已直接减生命，二者分开。** 当前代码采用伤害账本：后续投递看到的是更新后的盾、资源、空中状态及已生效效果，生命伤害则等 R5 分配祝福后在 R6 统一扣除。日志中出现“受到伤害”，也不代表此时已经判死。

## 七、R5：逐玩家、逐伤害分配祝福

所有攻击和回调完成后，按本回合行动者的座位升序处理祝福分配。

对每名玩家：

1. 汇集以该玩家为目标的生命伤害事件，不合并不同来源、不同段或多次反噬。
2. 仅对原伤害 `d > 1` 的事件提供分配选项；整数祝福无法合法减少 1 或 0.5 伤害而仍保持最终伤害大于 0。
3. 没有祝福值或没有可减伤事件时自动跳过；否则暂停，由该玩家统一提交这些事件的分配。
4. 每次用量 `q` 须为非负整数，满足 `q ≤ ceil(d)-1`，且全部事件用量之和不超过该玩家现有祝福值。省略某事件表示用 0。
5. 扣除实际花费的祝福，写回各事件的减伤量，再处理下一名玩家。

本阶段可以使用 R2 凤鸣九天刚获得的祝福。真伤同样可以按这套逐事件规则减伤；体力流失不是伤害，不提供祝福分配。

网页的 1～5 快捷按钮和输入框只是提交这份分配的方式，不增加额外结算阶段。

## 八、R6：统一扣血、判死和清理死亡目标

1. 对伤害账本中每条事件，扣除 `原伤害 - 祝福用量`。
2. 所有事件扣除完成后，统一将最终生命 `≤ 0` 的玩家判为死亡；生命可以为负数。
3. 移除目标已经死亡的持续攻击实例。来源虽死亡、目标仍活的旧持续攻击继续保留。

生命已经包含 R1a 的体力流失。R2 治疗已经生效且先按生命上限截顶，此处不重新按净伤害补算治疗。例如：

- 5 生命时用回一滴血，再受到 2 最终伤害，结算后为 3 生命。
- 1 生命时成功回复到 2，再受到 2 最终伤害，结算后为 0，死亡。
- 受到本足以致死的攻击，不会取消自己此前的造盾、法术、已经入队的攻击或命中收益。

没有中途濒死、死亡打断或复活阶段。死亡后的后续新行动，从下一回合起被排除。

## 九、R7：存活者必要弃置

按座位升序检查存活者，死亡者不再要求作弃置选择。

同时检查：总盾位不超过 5、同名持有物通常不超过 2 件、同种生产器最多 1 件、四种元素盾合计最多 2 件、生产器合计最多 2 件。幽灵盾按剩余层数占盾位。

不超限则继续；超限则暂停，让玩家从当前合法的**必要弃置方案**中选择。每个方案都必须满足：弃置后全部上限合法，且不能把其中任何一件放回而仍然合法。

这是“不多弃”的必要性要求，不承诺所有方案都弃置相同件数，也不是允许玩家任意主动丢弃装备。相同状态的盾忽略实例编号去重；只有一种实际弃置结果时自动完成，不要求玩家选择。

弃置结果不追溯改变本回合已发生的免疫、挡伤或死亡。完成后继续检查下一名存活者。

## 十、R8：确定胜负并完成回合维护

所有必要弃置完成后：

1. 计算存活者：一人存活则其获胜，无人存活则平局，两人及以上则对局继续。
2. 根据伤害账本记录本回合是否产生实际生命伤害，并将当前编号保存为“已完成回合”。
3. 引擎把内部回合编号加 1。
4. 删除结束回合早于新回合编号的持续法术状态（含防御、范围免疫、钻心咒）及持续/延迟攻击实例。
5. 返回完整结果，包括下一状态、已完成回合号、伤害账本、日志、胜负和获胜者。

有效区间的结束回合包含在内。例如 `start=3, end=5` 的实例参加第 3、4、5 回合，在准备第 6 回合时被清理。

三个持续闪避法术在 t 施放、持续 N 回合时为 `[t,t+N-1]`；钻心咒仍为 `[t+1,t+15]`；普通持续攻击仍为 `[t,t+N-1]`，飞刀为 `[t+1,t+1]`。不能把三者起算规则混为一谈。

固有回合防护保存在本次结算对象中，下回合重新登记；实际基础动作历史保留。本回合消耗的资源、盾和层数，以及仍有效的持续效果，随状态保留。

**实现细节：当前引擎即使已经得出胜负，也会完成第 3～4 步。** 对外应以“已完成回合号”展示本回合；房间服务见到终局后不会再开启新回合选招。开始新局则重新创建初始状态。

## 十一、中途选择怎样暂停和恢复

| 选择类型 | 所在阶段 | 谁选择 | 继续的位置 |
| --- | --- | --- | --- |
| 小电移除装备 `shock` | R2 | 受术者 | 移除选中的一件装备，完成当前法术，再继续剩余法术。 |
| 同位置承伤盾 `shield` | R4 | 受伤者 | 对选中盾执行本次交互；需要穿透继续时，仍留在同一投递。 |
| 祝福分配 `blessing` | R5 | 受到对应伤害的玩家 | 扣祝福、登记分配，再处理下一名玩家。 |
| 必要弃置 `discard` | R7 | 超限的存活者 | 移除该方案列出的装备，再继续容量检查。 |

暂停时保存阶段、当前游标和选择请求编号。恢复必须匹配当前请求及其所属玩家，并验证答案合法。继续执行时不重新扣成本、不重新施法、不重新生成攻击，也不重复命中收益。

当前小电和承伤盾先将完全相同的盾合并为一类，只在不同候选类别多于一种时询问；祝福和必要弃置按各自上述条件询问。这些条件和选择所在阶段不同，不应为了统一界面而移到回合末一起处理。

## 十二、房间服务在引擎前后做什么

这部分属于[房间服务](../server/index.js)，不属于独立引擎的 R0～R8：

观众单独保存在房间观战名单，不进入本局引擎玩家列表、座位、目标、存活或胜负判定；中途加入和退出不会重新开始结算，也不会调整当前倒计时。观众在局外主动入座后，才可参与下一局。详见 [观战系统](v2-观战.md)。

1. **进入 R0 前**：收集并隐藏各自锁定的行动；全员锁定或选招超时后调用引擎。当前超时未提交者补基础大臂。
2. **引擎暂停时**：把选择交给指定玩家；当前默认超时答案为零祝福分配或第一项装备方案，离场等情况由服务层代选，然后调用恢复函数。
3. **R8 返回后**：应用网络离场导致的弃权，将相应玩家生命设为 0，再清理指向这些玩家的持续攻击，重新计算最终存活者和胜负。纯引擎得出的胜负不是这一步的替代品。
4. **结果展示**：保存战报，终局时记录一次胜场；默认有生命伤害或体力流失展示 5 秒，二者都没有则展示 2 秒，然后进入下一回合选招或终局等待。

动画是这些已确认状态变化的展示，不会延后伤害、改变互攻或插入新的游戏效果。

## 十三、以后增加机制时要明确的时序

下面是新增机制需要回答的问题，不表示这些机制已经存在，也不替未来版本预先作决定。

| 新机制涉及的内容 | 需要明确的阶段关系 |
| --- | --- |
| 修改资源、成本或生产收益 | R0 校验读什么状态；R1 支付前还是支付后修改；是否影响当回合已确定的其他行动。 |
| 取消、打断或封禁行动/法术 | 在 R1、R2 还是 R4 介入；是否退费；已发放收益、固有防护和已生成持续实例如何处理。 |
| 新造物、移除物或容量变化 | 是否在 R1 建立；能否在 R2 被移除；何时参与免疫或承伤；仍在 R7 整理还是增加其他检查点。 |
| 改变目标、点数或攻击次序 | 在 R3 固定之前改变，还是 R4 动态改变；后者是否重排队列、重判互攻及更新原始意图。 |
| 新防护、穿盾或反弹 | 在对空、免疫、防法、命中、持有盾的哪一步介入；反弹若生成新攻击，应如何排序、判互攻及限制循环。 |
| 命中、掉盾、造成伤害等触发器 | 触发的是哪一种事件；盾挡是否触发；多段、溅射、穿过多面盾分别触发几次；回调在下一份投递前还是回合末执行。 |
| 治疗、吸血、护血或死亡效果 | 依据 R2 已截顶的生命、R4 伤害账本还是 R6 扣血后的生命；是否改变当前统一判死约定。 |
| 持续、叠加或延迟效果 | 何时建立，施放回合是否计入，何时生成攻击，来源/目标死亡时如何保留，何时到期清理。 |
| 需要额外玩家选择 | 插在什么事件中暂停，谁选择，允许选什么，恢复时从哪一步继续。 |

每次修改，至少检查受影响的阶段先后、同阶段的稳定顺序，以及暂停恢复是否仍能保证每份效果只执行一次。涉及已有招式时同步补充判例，避免只写新机制而遗漏它与互攻、盾、祝福和死亡的交互。


### V2 剩余时长显示修正（2026-11-25）

R2 三个闪避法术当回合即生效。对有效状态，回合中剩余时长为 `end-当前回合+1`；R8 已执行的结果展示阶段改用 `end-(已完成回合+1)+1`，不重复计入已经结束的回合。后者小于等于 0 的状态不再展示。幽灵闪首回合结束后只显示剩余 1 回合。


### V2 同盾与地震修正（2026-11-26）

同盾以除实例编号外全部状态相同为准；不同盾类型、不同幽灵层数仍保留选择。小电和承伤只显示每类的一个代表；超限弃置按保留盾的实际状态集合去重，只有一种结果就自动完成。自动处理仍遵守位置、穿透及必要弃置条件。

地震对实际“闪电盾”恢复普通交互，由其成本中的 S 触发免疫，生命和盾均不消耗；免疫发生在承伤和穿透之前。其他已有盾交互不受此修正影响。


### V2 阶段反射补充（2026-11-26）

1. R1b 钻心咒新增当回合无敌（1 级免伤、1 级免控）。
2. R1c 锤锤锤先取消三连踹/太阳拳的反射法术；攻击本体继续保留，本次被取消法术的同名库存不增加。穿云箭条件防护是固有，不能取消。
3. R2 每份有害法术在检查目标免控前，按所有未被取消的太阳拳一次性改写目标：非指定对手来源改为原来源自己。重定向目标和游标保存到续结中；只反射本阶段小电、钻心咒，不反射 R1 禁法或 R4 打落。
4. R3 每份攻击先按原目标确定点数/段伤/标签，再按未被取消的三连踹改写实际接收者。多个反射者分别追加一份对原来源的自攻击，保留重复，不递归。改写完成后才确定互攻，自攻击不自抵消。
5. R4 穿云箭使用者面对来源不是其指定目标的攻击，在免疫步骤获得 2 级免伤；按原攻击来源比较，不按反射者比较。自攻击仍正常检查所有适用防护。

完整定义及例外见 [V2 实现说明](v2-实现说明.md)第 9 节；这里不引入新的联网阶段或交互选择。
