“点压”采用原稿的严格数值定义：双方攻击互相指向对方，而且自己的点数严格更高。它与“特殊克制”“最终是否被压制”分开记录；等点抵消、攻击其他人、刀点刀克制、弧光反转，均不会自动变成数值点压。

## 已接入的通用结构

- 判定仍独立于房间服务与玩家选招界面，所有续结状态可序列化，入口不修改传入对象。
- 持续攻击调度支持群体：不再强制要求一个锁定单体目标；群体持续攻击不因不存在 `targets[0]` 而被丢弃。每回合重新展开有效目标，来源死亡不取消攻击，但不复活旧死亡来源。
- 多层盾统一按装备的 `grade=ghost` 判定，剩余层数决定盾位、一般穿透扣层、完整盾穿透特例；不再写死只认“幽灵盾”这个 ID。
- 盾实例支持独立预算属性，选盾/弃置的同质去重会考虑预算和层数。塑料盾制造前即检查唯一持有限制，不能利用回合末整理前的窗口同时持有两面；同名库存不计入真实盾数量。
- 攻击意图与伤害投递分开保存。零段攻击仍以所选目标和点数参与互攻比较，但不生成命中、扣血或盾消耗。多段攻击可以逐段暂停、序列化并恢复，已经消费的盾、成本和库存不会重复处理。
- 攻击队列可记录每段自己的防法、经过回合数、动态伤害、严格点压及条件真伤。沉默/寂灭盾沿用现有 R3 快照约定：在小电等 R2 效果完成后按当前真实盾数量和层数计算加点；持续攻击每回合重算。R4 丢盾不追溯重排队列、不改已固定的互攻结果。
- 防护器的额外防法按 R4 当前真实持有状态读取，盾被前一段消耗后，后续段立即失去该防法；这与攻击点数在 R3 固定分开处理。额外防法能参与“Z/C 或法术防”的基础防法分支，但不把实际基础动作改成别的动作，五连镖的条件伤害等仍按实际行动判断。
- 新招式的中文、全拼和拼音首字母搜索已登记。合成成本统一显示真实盾材料；装备详情统一显示层数或预算。
- [招式清单.yaml](招式清单.yaml)记录所有条目的实现状态、法术分类、资源成本、装备属性及特殊组件。该清单仍为人工审阅文件，游戏运行读取 `rules/catalog.js`。

## 当前回合时序

R0校验 → 防护器开局失效 → R1a体力流失 → R1b成本/新盾/固有防护 → R1c禁法与青蛙自爆 → R1d库存 → R2独立法术 → R3攻击快照/改目标/排序/互攻 → R4逐段投递与即时生命变化 → R5保留编号、不再集中分配祝福 → R6统一判死 → R7必要弃置 → R8胜负和到期维护。

R4每段的顺序：压制 → 对空 → 普通免疫 → 防法 → 喜马拉雅闪 → 命中与盾（含塑料盾） → 天闪选择、受击者流失x体力、来源治疗x → 本次祝福 → 诅咒倍率 → 即时扣血 → 万阳即时回复 → 命中回调。

天闪或祝福选择暂停整个结算。当前段处理完之前，不开始下一段；恢复时不重复扣成本、发库存、耗盾或治疗。体力流失不是伤害，完全绕过本链。

设原段伤害d=6，天闪选择x，祝福花费q，诅咒倍率k（无诅咒1、有诅咒2），实际伤害为`(d-2x-q)×k`，另有x点体力流失；总生命减少为`x+(d-2x-q)×k`。若`d-2x=0`，q只能为0且不询问祝福；否则q为整数并保持剩余伤害严格大于0。例：x=3，无论有无诅咒，伤害为0但流失3体力；x=2、q=1、k=2，则伤害2、体力流失2，总共少4生命。普通回一滴血仍在R2按上限截顶。

天闪伤害账本记录`baseAmount=d-2x`、`multiplier=k`、`blessingSpent=q`、`amount=(d-2x)×k`、`blessing=q×k`、`finalAmount=(d-2x-q)×k`；x点流失单独记入`lifeLoss`。旧展示层的`amount-blessing`仍等于实际伤害，祝福库存只扣`blessingSpent`。R6不重复扣血，仅统一判死。其他非天闪攻击没有这项2x修正和额外流失。
